# Ink Text Implementation Plan

**Goal:** An `ink_text` board element: the model sends a string, the app renders it as handwriting-look ink strokes. The "never simulated handwriting" style rule is removed; the storage rule (tutor content never enters the learner's PencilKit drawing) stays.

**Why this shape:** models write text well and letterform geometry badly. The app owns the glyphs (the E2ESeedFixture already proves the machinery: a `[Character: Glyph]` stroke-template table + `makeLine` layout cursor, rendered through ink). Production lifts that machinery out of test code, extends coverage, and renders in the tutor scene layer with tapered ink-look strokes — visually ink, architecturally tutor-owned.

## Wire contract (both lanes build to this)

Element kind `ink_text`, flat wire fields like every kind: `id`, `kind`, `x` (left edge, board points), `y` (top edge), `text` (≤ 400 chars, `\n` for line breaks), `size` (cap height in board points, 8–256), plus the seven shared style fields (`stroke` = ink color; `opacity`, `rotation` honored; `fill`, `stroke_width`, `dash` ignored by this kind).

## Task A — Swift (glyphs, renderer, element)

Files: create `MathTutor/DesignSystem/InkGlyphs.swift` (glyph data + layout), `MathTutor/Features/Board/InkTextRenderer.swift`; modify `MathTutor/Domain/BoardScene.swift` (element + kind + case + WireElement fields, lenient path already handles unknowns), `BoardSceneRenderer.swift` (draw + bounds arms), `E2ESeedFixture.swift` (fixture element — the allCases coverage test at BoardSceneTests:181 demands it; also migrate the fixture's own seeded ink lines to the shared glyph table so one table serves both), tests (`MathTutorTests/InkTextTests.swift`).

1. **Glyph data**: lift the fixture's `Glyph` shape (unit-box stroke polylines + advance width) into `InkGlyphs`. Coverage: a–z, A–Z, 0–9, space and `. , ! ? ' " ( ) + - = × ÷ / : ; → ✓ ✗ %`. Source geometry either by vendoring the public-domain Hershey simplex/script dataset as a data file (provenance comment required; verify license-clean) or by extending the fixture's hand-authored style to full coverage — implementer's call, but a pixel test must show a full pangram plus digits legibly at size 24.
2. **Renderer**: strokes → smoothed path (the fixture's quad-midpoint smoothing exists in BoardSceneRenderer's freehand arm) → ink-look: variable-width tapered stroke (filled outline path; width tapers toward stroke ends), round caps. Deterministic per-character jitter (±2% of size, seeded from the element id + char index) so it reads organic but captures stay byte-stable. Draw arm + bounds arm (layout-computed size; degenerate text → `.zero`, consistent with siblings). Raster path goes through the existing layer-view machinery untouched — this kind is synchronous (no store, no notification): glyph layout is pure CPU, no async artifact.
3. **Tests**: decode from flat wire JSON; layout bounds (multi-line, empty text degenerate); pangram pixel test (ink pixels present, top/bottom taper distinct from uniform-width — assert width variance); determinism (two renders byte-identical); unknown-glyph fallback (a character outside the set renders a placeholder underscore, never crashes, logged like unknown kinds).

## Task B — Server (schema, prompt)

Files: `server/app/tutor/board_scene.py` (`InkTextElement`, `MAX_INK_TEXT_CHARS = 400`, union), `server/app/tutor/tools.py` (arm + description edits), `server/app/tutor/prompt.py`, tests (`test_board.py`, `test_tools.py`, `test_prompt.py` — re-pin the SYSTEM_PROMPT sha256).

1. **Schema**: `InkTextElement` (`kind: Literal["ink_text"]`, x, y, text ≤ 400, size 8–256, `_Identified` style), strict arm, kind-set test extended, budget bound moved consciously per the rule beside it.
2. **Rule flip in the `update_board` description**: delete the "structured text and geometry, never simulated handwriting" clause; keep "This tool never touches the learner's own PencilKit ink" verbatim (that is storage, not style — it is what keeps their undo history theirs). Add `ink_text` to the kind-routing sentence: handwriting-look notes, hints, margin comments, warm annotations; `math_text` still owns notation; `text` stays for compact labels.
3. **Prompt** (per the user): BOARD section gains a line — write on the board like a real teacher: `ink_text` for hints, encouragement, margin notes, worked commentary, and use it often; notation stays `math_text`. TOOLS list unchanged (update_board already listed). Re-pin the hash with a dated comment.
4. **Capture caveat comment**: in the arm description, one clause telling the model its own ink_text appears handwritten in board captures — when grading, learner work is the pen ink it did not draw (scene JSON lists its own element ids).

## Order and rules

Tasks A and B are file-disjoint and run in PARALLEL (opus). Reviews follow each (established SDD loop).
